A **Git Workflow** defines how 
a team creates branches, 
synchronises changes, 
reviews code and merges work 
into the shared repository.

---

There is no one-size-fits-all workflow. The strategy must be tailored to the team and the delivery cadence, whilst keeping the cognitive overhead low.

```text
Branch → Commit → Sync → Pull Request → Review → Merge
```

> [!tip]
> A good workflow should be easy to explain, scale with the team and allow errors to be corrected without relying on fragile procedures.
